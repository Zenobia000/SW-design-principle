# 深度指南

> 從理論到實踐 - SOLID 原則深度解析

## 📚 內容說明

本目錄包含 5 個深度實戰指南,每個對應一個 SOLID 原則,涵蓋:
- ✅ 核心理念與判斷標準
- 🔥 設計經驗與最佳實踐
- ⚠️ 常見反模式與陷阱
- 🛠️ 實戰技巧與重構策略
- 💡 無招勝有招的內化心法

---

## 📖 指南列表

### [SRP-深度實戰指南.md](./SRP-深度實戰指南.md)
**單一職責原則 - 職責分離的藝術** (20KB)

#### 核心內容
- 什麼是「職責」?如何判斷職責邊界?
- 按「變更的源頭」分離職責
- 內聚性檢查法
- 提取直到痛苦消失

#### 反模式
- God Object (上帝物件)
- Shotgun Surgery (散彈槍手術)
- Feature Envy (特性依戀)

#### 無招心法
- 直覺分離
- 自然分層
- 小步重構
- 命名驅動設計
- 測試即設計

**何時閱讀**: 當你的類變得龐大、難以命名、測試困難時

### [OCP-深度實戰指南.md](./OCP-深度實戰指南.md)
**開放封閉原則 - 擴展的智慧** (25KB)

#### 核心內容
- 什麼是「開放」與「封閉」?
- 識別變化軸
- 穩定的依賴於抽象
- 抽象屬於高層

#### 擴展策略
- 策略模式 (Strategy Pattern)
- 模板方法模式 (Template Method)
- 裝飾器模式 (Decorator Pattern)
- 插件架構 (Plugin Architecture)

#### 無招心法
- 識別變化模式
- 痛苦驅動設計
- 抽象的層次
- YAGNI vs 可擴展性的平衡
- 遞延決策

**何時閱讀**: 當你頻繁修改同一段代碼、if-else 分支不斷增加時

---

### [LSP-深度實戰指南.md](./LSP-深度實戰指南.md)
**里氏替換原則 - 繼承的真諦** (24KB)

#### 核心內容
- 什麼是「可替換性」?
- LSP 的契約:前置條件、後置條件、不變條件
- 行為的一致性比類型繼承更重要

#### 違反信號
- 類型檢查 (isinstance)
- 空實現或拋出異常
- 子類加強了前置條件
- 子類減弱了後置條件

#### 無招心法
- 行為替換而非類型繼承
- 契約思維
- 最少驚訝原則
- 組合優於繼承
- 忘記 LSP

**何時閱讀**: 當你需要 isinstance 檢查、子類拋出 NotImplementedError 時

---

### [DIP-深度實戰指南.md](./DIP-深度實戰指南.md)
**依賴倒置原則 - 控制依賴的方向** (24KB)

#### 核心內容
- 什麼是「依賴倒置」?
- 識別高層與低層
- 抽象的穩定性
- 抽象屬於高層(關鍵洞察)

#### 依賴注入模式
- 構造器注入 (推薦)
- 方法注入
- 屬性注入
- DI 容器

#### 架構應用
- 六邊形架構 (Hexagonal Architecture)
- 清晰架構 (Clean Architecture)
- 分層設計

#### 無招心法
- 依賴方向的直覺
- 抽象的粒度感
- 讓編譯器/類型系統幫你
- 依賴圖的心智模型
- 忘記 DIP

**何時閱讀**: 當你的代碼難以測試、難以切換實現、耦合度高時

---

### [ISP-深度實戰指南.md](./ISP-深度實戰指南.md)
**介面隔離原則 - 最小化接口的藝術** (25KB)

#### 核心內容
- 什麼是「接口污染」?
- ISP 的本質:客戶端視角
- 角色接口 (Role Interface)
- 頭部接口 (Header Interface)
- 粒度權衡

#### 設計哲學
- 發現而非發明
- 內聚性檢查
- 穩定性分層

#### 實戰模式
- CQRS-lite (命令查詢責任分離)
- 能力接口 (Capability Interface)
- 最小權限接口

#### 無招心法
- 接口是契約的最小集
- 一次只做一件事的接口
- 接口的演化
- 忘記 ISP

**何時閱讀**: 當你的接口有很多方法、實現類有空方法或拋異常時

## 🎓 學習建議

### 初學者 (第一次閱讀)

1. **按順序閱讀**: SRP → OCP → LSP → DIP → ISP
2. **重點章節**:
   - 核心理念
   - 設計經驗
   - 常見反模式
3. **跳過**: 複雜的重構技巧(第二次再看)
4. **時間**: 每個指南 1-2 小時

### 中級學習者 (深入理解)

1. **有選擇地閱讀**: 根據當前遇到的問題
2. **重點章節**:
   - 設計經驗
   - 實戰技巧
   - 重構策略
3. **實踐**: 每讀完一個章節,找真實代碼練習
4. **時間**: 每個指南 2-3 小時

### 高級學習者 (融會貫通)

1. **直接閱讀**: 「無招勝有招」章節
2. **重點**:
   - 心法內化
   - 原則的邊界與例外
   - 何時打破規則
3. **實踐**: 指導他人,通過教學深化理解
4. **時間**: 每個指南 30 分鐘

## 📋 閱讀檢查清單

完成每個指南後,問自己:

### 理解層面
- [ ] 我能用自己的話解釋這個原則嗎?
- [ ] 我能判斷代碼是否違反這個原則嗎?
- [ ] 我理解為什麼要遵守這個原則嗎?

### 應用層面
- [ ] 我能識別常見的反模式嗎?
- [ ] 我知道如何重構違反原則的代碼嗎?
- [ ] 我在實際項目中應用過這個原則嗎?

### 內化層面
- [ ] 我知道何時應該遵守這個原則嗎?
- [ ] 我知道何時可以打破這個原則嗎?
- [ ] 我能自然地寫出符合原則的代碼嗎?

## 💡 學習技巧

### 1. 理論與實踐結合

```
閱讀指南 → 看 Notebook 範例 → 重構真實代碼
```

### 2. 循環學習

```
第一遍:理解概念 (略讀)
第二遍:深入細節 (精讀)
第三遍:內化心法 (只讀「無招勝有招」)
```

### 3. 教學相長

- 向同事講解你學到的
- 寫技術文章總結
- 做 Code Review 時應用

### 4. 持續實踐

- 每週重構一個類
- 每月重構一個模組
- 每季度重構一個系統
